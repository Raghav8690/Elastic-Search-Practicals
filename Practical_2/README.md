# Practical 2 - Employee Dataset & CRUD with Elasticsearch

A Python practical that builds a 120-record employee dataset and performs the
standard index/document lifecycle operations against Elasticsearch using the
REST API (via the `requests` library).

## Files

| File | Description |
|------|-------------|
| `generate_employees.py` | Generates a reproducible dataset (seed 42) and writes `employees.json`. |
| `employees.json` | The dataset: 120 employee records (field layout below). |
| `main.ipynb` | Jupyter notebook that executes tasks 1-10 against Elasticsearch (originally `main.py`). |
| `setup_kibana.py` | Creates the Kibana data view + charts + "Employee Overview" dashboard via the API. |
| `employees_kibana_objects.ndjson` | Saved-objects export generated by `setup_kibana.py` (manual import fallback). |
| `README.md` | This file. |

Each record looks like:

```json
{
  "employee_id": 101,
  "name": "Rahul Mehta",
  "department": "Support",
  "designation": "Support Engineer",
  "salary": 51000,
  "city": "Pune",
  "joining_date": "2019-07-26",
  "active": true
}
```

## Prerequisites

1. Elasticsearch + Kibana running from `Practical_1`:
   ```powershell
   cd ..\Practical_1
   docker compose up -d
   ```
   Wait until `http://localhost:9200` responds.
2. Python 3 with `requests` installed (already present in this environment).

The base URL can be overridden with the `ES_URL` environment variable
(default `http://localhost:9200`).

## How to run

```powershell
cd "C:\D-Drive\Elastic Search Practicals\Practical_2"
python generate_employees.py   # writes employees.json (120 records)
# run main.ipynb in Jupyter       (executes tasks 1-10)
python setup_kibana.py         # creates the Kibana data view + dashboard
```

## Visualize in Kibana

`setup_kibana.py` creates (idempotently, via the Kibana saved-objects API):

- Data view **employees** (index pattern `employees`, time field `joining_date`)
- Lens charts: Average Salary by Department, Headcount by City, Total Employees,
  Hires Over Time
- Dashboard **Employee Overview** with all four panels

Then open:

```
http://localhost:5601/app/dashboards#/view/emp-dashboard-overview
```

Set the time picker to **Last 10 years** (the `joining_date` values are
2018-2025, so the default "Last 15 minutes" shows nothing). You can also explore
the raw documents under **Analytics → Discover** with the `employees` data view.

If the automated import ever fails, import `employees_kibana_objects.ndjson`
manually via **Stack Management → Saved Objects → Import**.

## Task map

| # | Task | REST call used |
|---|------|----------------|
| 1 | Create `employees` index | `PUT /employees` (settings + mappings) |
| 2 | Insert via Index API (explicit IDs) | `POST /employees/_doc/{employee_id}` |
| 3 | Insert with auto-generated IDs | `POST /employees/_doc` |
| 4 | Retrieve by ID | `GET /employees/_doc/{id}` |
| 5 | Update fields (full replace) | `PUT /employees/_doc/{id}` |
| 6 | Partial update | `POST /employees/_update/{id}` with `{"doc": {...}}` |
| 7 | Delete a document | `DELETE /employees/_doc/{id}` |
| 8 | Delete the index | `DELETE /employees` |
| 9 | Recreate the index | `PUT /employees` |
| 10 | Bulk insert | `POST /_bulk` (`application/x-ndjson`) |

After a successful run the `employees` index exists with all 120 documents
loaded via the Bulk API.

## Notes

- The index uses `number_of_shards: 1` and `number_of_replicas: 0` so it stays
  **green** on a single-node cluster.
- `main.ipynb` is idempotent: it drops an existing `employees` index before
  starting, so it can be re-run safely.
- `setup_kibana.py` overwrites the same dashboard/visualization IDs, so it can
  be re-run safely.
